# Moodle-first alpha 0.22

This product decision supersedes earlier descriptions of mandatory workspace encryption and local-only AI. Alpha releases do not promise backwards compatibility. Earlier encrypted profiles are left untouched; the application starts a new readable SQLite workspace and explains that Moodle must be reconnected.

See [0.23 student support and interface](student-experience.md) for reviewed Moodle/curriculum links, estimated study calendars and course adaptation.

## Student workflow

Onboarding starts with the school Moodle connection and separate course selection, followed by AI configuration and optional programme PDFs. Any step can be postponed. Completion is persisted and survives restart. The same configuration remains available in the normal screens.

Moodle is the primary follow-up source, while personal materials and activities supplement it. Home shows pending imported tasks and recently updated personal submissions with published feedback. A student can prepare a work for the existing difficulty-confirmation and guided-practice cycle. Planning, materials, tutoring, exercises, flashcards, goals, portfolio, projects and reports remain available. The tutor receives bounded assignment instructions, original response excerpts, feedback and source URLs from the selected subject. Withdrawn work and other subjects are excluded. Grades and feedback never automatically establish mastery.

The connector's nine-function allowlist is unchanged. Neither onboarding, curriculum import, account AI nor a local practice action can submit work, grade it or change Moodle.

## Programme PDF

Select one subject and a PDF. The isolated local reader extracts all pages. Extraction sends each nonempty page fragment to the selected AI, with overlaps rather than silent truncation, and validates the returned schema and literal source quotes. A document requiring more than 600 fragments must be split before inference; scanned or mixed PDFs use the selected multimodal model to transcribe every page. Since 0.23, visual PDFs can contain up to 300 pages and are processed in five-page batches. The first ten prepared images are retained as previews; remaining source pages must be checked in the original PDF. All page transcripts are processed, without a partial save. The proposal includes reduced source images and transcripts for comparison; visual quotes are checked against the AI transcript and must be compared with the source image. Cancellation or invalid output leaves no partial curriculum.

The proposal identifies units, competencies, criteria, contents and outcomes. Descriptions can retain objectives, timing, assessment and methodology. Missing categories and empty fragments are flagged. The student edits titles, codes and descriptions, removes unwanted rows and explicitly confirms. Page numbers and source quotes are retained for inspection. Dates, dependencies and curriculum-unit links are not inferred into operative scheduling automatically; they need review in the existing editor.

Confirmation atomically saves the full extracted text as a material and inserts selected units/curriculum. Same-text reimports are rejected to avoid duplicate units. Drafts live only in memory, expire after 30 minutes, and are invalidated by restoration, deletion, reset or mock-exam entry. An unsupported or inaccurate AI answer is rejected rather than treated as a complete extraction. Coverage and educational interpretation still require review.

## AI choices

The catalog contains six pinned, checksum-verified GGUF downloads: text-only Qwen 2.5 1.5B/3B and Qwen 3 4B/8B, plus multimodal Gemma 4 E2B/E4B. Qwen thresholds are 4/8/12/20 GiB total RAM; Gemma thresholds are 12/20 GiB. Recommendations prefer a visual model when memory permits. Gemma downloads include the separately verified Q8 visual projector (approximately 3.40/5.15 GB combined respectively); readiness requires both assets. Text-only models reject image reading with an actionable message. Hardware discovery reports CPU, memory and Windows GPU names; dedicated NVIDIA memory is reported when its driver tool is available, otherwise unknown. These are initial memory heuristics, not performance measurements. Since 0.23, a pinned Vulkan runtime can use a detected GPU, with a CPU-only option and automatic CPU fallback. Selected/downloaded models persist under `Data/models`.

Account integrations use unmodified, separately installed native executables selected by the user. No API key is requested. Since 0.23, they reuse the official CLI's existing session and honor its configured account home. Codex uses App Server and Claude uses its noninteractive CLI. Browser sign-in is offered only when the official tool reports no connected account. Tutor never copies or parses credential files. Leaving an account in Tutor returns to local AI and revokes external-context authorization without logging out the shared CLI. Queries run from an empty application working directory; Codex overrides configured MCP servers, app tools, shell and web access, while Claude disables tools, MCP and settings sources. Availability and usage limits depend on the user's account.

Activating an external provider requires explicit student/family authorization for necessary query, selected images, material, work and feedback excerpts. That authorization applies across AI features, including programme extraction and rubric/observation proposals; returning to local AI stops external use. Child environments exclude inherited API keys, Moodle credentials and unrelated project variables. Account agents run from an empty working directory with built-in tools disabled/restricted, no MCP servers, and no approval channel. Codex receives selected prepared images as explicit local-image inputs in an ephemeral thread; private temporary images are removed on completion/cancellation. Claude receives base64 images through newline-delimited streaming input. They remain learning providers, never Moodle operators. Account tool authentication files follow the official tool's own storage behavior; protect the complete `Data` folder.

Official references: [Codex App Server](https://developers.openai.com/codex/app-server/), [Claude CLI](https://code.claude.com/docs/en/cli-reference), [Claude product integration conditions](https://code.claude.com/docs/en/legal-and-compliance). Model metadata comes from the pinned official Qwen and ggml-org Gemma Hugging Face repositories recorded in `electron/model-catalog.ts`.

## Image and scanned-document reading

Tesseract and trained language assets have been removed from dependencies and packaging. A network-denied utility process validates local file dimensions/size, renders selected PDF pages, applies rotation and produces bounded JPEGs without metadata. The selected multimodal AI interprets these images. There are no fabricated word boxes or confidence percentages. The original prepared image, model/provider provenance, first transcript and immutable human reviews remain linked to derived materials or ungraded personal attempts. Recognition alone cannot establish mastery. Model downloads verify both weights and visual projector; failed downloads remove partial files and retain already verified assets.

A native Gemma 4 E2B CPU check on this host transcribed a synthetic image containing `2 + 2 = 5` without solving/correcting it. A separate native structured-text request also extracted a unit title as schema-conforming JSON. These establish actual image/text input, not handwriting or arbitrary document accuracy. The desktop capture regression uses real preparation and a deterministic vision response; scanned curriculum coverage likewise uses a deterministic extraction response. Run `npm run test:multimodal` for the separate native-model check. See [Google model card](https://ai.google.dev/gemma/docs/core/model_card_4) and [Google llama.cpp integration](https://ai.google.dev/gemma/docs/integrations/llamacpp).

## Storage and portable behavior

`Data/learning.sqlite` is readable educational history, written through a flushed temporary file and atomic replacement. No workspace password is required. Moodle tokens and the derived semantic cache retain separate encryption with a Windows-protected, device/user-specific key. A moved workspace can open its educational history on another Windows account/computer, but Moodle must be reconnected; that second-host scenario still needs direct qualification. Account-provider sign-in may also need repeating. Optional encrypted exports remain supported. Educational backups exclude account executable paths, provider activation and external-context authorization. Restoration cannot activate an external account; review setup again afterward.

The previous alpha's files are not deleted, decrypted or silently migrated. No backward compatibility is promised for databases or backups. The app remains portable Windows x64 and unsigned.

## Verification boundaries

Domain checks cover readable SQLite restart, atomic programme insertion/deduplication, source-quote/page rejection, model pins/recommendation, child-environment isolation, subject-scoped Moodle context and the Codex protocol with a deterministic child-process double. The desktop orientation test connects two synthetic Moodle courses through the real UI, chooses among six models, checks the cloud-consent gate, reads a real local PDF with a deterministic AI response, edits/confirms the proposal and restarts.

The 0.22 checks used fresh application-specific account directories and only verified signed-out status. The 0.23 implementation reuses existing official CLI sessions. Both providers completed real tutoring, structured JSON and selected-image requests with synthetic context on this host. Full extraction quality with arbitrary school programmes, a second computer/account and educational efficacy remain separate unverified scenarios. See the current versioned qualification; historical artifacts retain their original limits.
